Data Warehousing & Data Mining (DWDM)

Comprehensive documentation on the problem statement, architectural star schema design, OLAP multidimensional cubes, and machine learning data mining algorithms implemented in MarketMind.

1. Problem Statement & Motivation

Modern e-commerce platforms process thousands of transactions daily. However, operational databases (OLTP) are optimized for transactional writes rather than analytical decision-making. Retail executives face three critical analytical challenges:

Data Silos

Raw operational tables slow down multi-period aggregation and historical trend queries.

Unseen Co-purchases

Retailers lack mathematical visibility into items purchased together, missing cross-sell bundling.

Customer Churn

Without behavioral segmentation, high-value and at-risk shoppers receive identical generic marketing.

MarketMind addresses this problem by decoupling analytical queries into a dedicated Star Schema Data Warehouse and applying unsupervised machine learning (Apriori and K-Means) to derive actionable intelligence.

2. Project Objectives

  • Star Schema Implementation: Design and populate a dimensional data warehouse schema consisting of FactSales and four dimensions (DimDate, DimProduct, DimCustomer, DimOrder) at line-item grain.
  • Automated ETL Pipeline: Construct an automated ingestion workflow that validates schema, eliminates duplicates, filters corrupt records into a staging area, and assigns surrogate keys.
  • Market Basket Analysis (Apriori): Uncover hidden purchase associations, calculate Support, Confidence, and Lift metrics, and translate rules into plain-English marketing recommendations.
  • Customer Behavioral Segmentation (K-Means): Cluster customers into distinct personas based on standardized RFM features (Recency, Frequency, Monetary spend, and Average Order Value).
  • OLAP Multi-dimensional Operations: Provide interactive Roll-up, Drill-down, Slice, Dice, and Pivot exploration alongside real-time SQL inspection.

3. Data Warehousing Concepts Used

Star Schema Architecture

MarketMind adopts a classic Kimball Star Schema. In this structure, a centralized FactSales table connects to surrounding de-normalized dimension tables via surrogate integer keys:

Table Name Type Surrogate Key Business Key Primary Attributes / Measures
FactSales Fact SalesKey N/A Quantity, UnitPrice, DiscountAmount, TotalAmount, ProfitMargin
DimCustomer Dimension CustomerKey CustomerID CustomerName, Country, Segment, FirstPurchaseDate
DimProduct Dimension ProductKey ProductID ProductName, Category, UnitPrice
DimDate Dimension DateKey (YYYYMMDD) FullDate Day, Month, MonthName, Quarter, Year, DayOfWeek, IsWeekend
DimOrder Dimension OrderKey InvoiceNo OrderDate, TotalItems, TotalOrderValue, OrderStatus
Granularity Definition

Grain: Exactly one row per order item. Defining the grain at the individual product line-item level avoids double-counting order totals when joining across product and customer dimensions, while retaining full fidelity for Apriori basket analysis.

Multidimensional OLAP Operations Demonstrated
Roll-Up

Summarizes data from daily transactions to monthly and yearly totals (moving up the hierarchy).

Drill-Down

De-aggregates summary data down into fine-grained components, e.g. yearly down to quarters or category down to individual items.

Slice

Filters the data cube by selecting a single dimension value (e.g., viewing sales exclusively for Category = 'Electronics').

Dice

Extracts a multi-dimensional sub-cube by specifying filtering criteria across multiple dimensions simultaneously.

4. Data Mining Algorithms Explained

A. Apriori Association Rule Mining (mlxtend)

The Apriori algorithm identifies frequent itemsets using candidate generation and the downward closure property: all non-empty subsets of a frequent itemset must also be frequent.

Support(A → B) P(A ∪ B)
Frequency of joint purchase
Confidence(A → B) P(B | A) = Sup(A∪B)/Sup(A)
Probability of B given A
Lift(A → B) Conf(A→B) / Sup(B)
Synergy ratio (> 1 = positive)
B. K-Means Customer Behavioral Clustering (scikit-learn)

Partitions $N$ customers into $K$ distinct behavioral clusters. Each customer is represented by a normalized feature vector:

  • Recency: Days elapsed since the customer's most recent order.
  • Frequency: Count of unique orders completed.
  • Monetary: Cumulative spend across all transactions.
  • AvgOrderValue (AOV): Monetary value divided by order count.
Features are scaled using StandardScaler (zero mean, unit variance) to ensure high-magnitude monetary values do not distort Euclidean distance computations during cluster centroid optimization.
